Trace propagation

The SDK injects a W3C traceparent header into every outgoing fetch / XMLHttpRequest whose URL matches any entry in tracePropagationTargets. The same trace id lands on the network breadcrumb's data.trace_id, so requests can be inspected from an error's breadcrumbs. Network failures and HTTP 5xx responses also report the browser request as the root span of that request's backend trace.

Glob syntax: * matches one path segment, ** matches across segments. Match anchors on the URL's host + pathname.

This fixture captures payloads locally. It does not create backend spans or send reports to AppSignal.
